
● config.json 기준으로 시나리오 설명합니다.

  { "local_port": 8080, "target_ip": "127.0.0.1", "target_port": 80 }

  ---
  시나리오 1: nc 양방향 채팅 (가장 단순)

  터미널 3개 필요.

  # 터미널 1 — "서버" 역할 (port 80 리스닝)
  nc -l -p 80

  # 터미널 2 — 프록시 실행
  cd ~/tunneling-proxy/build
  ./proxy --config ../config.json

  # 터미널 3 — "클라이언트" (프록시에 연결)
  nc localhost 8080

  터미널 3에서 타이핑 → 터미널 1에 출력
  터미널 1에서 타이핑 → 터미널 3에 출력

  양방향이 되면 forward_data + handle_connection 정상 동작 확인.

  ---
  시나리오 2: HTTP 프록시 (실제 웹서버 연결)

  # 터미널 1 — Python 간이 HTTP 서버 (port 80은 권한 필요하므로 8000)
  # config.json의 target_port를 8000으로 바꾸거나:
  python3 -m http.server 8000

  # config.json 수정
  { "local_port": 8080, "target_ip": "127.0.0.1", "target_port": 8000 }

  # 터미널 2 — 프록시 실행
  ./proxy --config ../config.json

  # 터미널 3 — curl로 프록시 통해 접근
  curl http://localhost:8080

  파일 목록 HTML이 출력되면 HTTP 트래픽 포워딩 성공.

  ---
  시나리오 3: 다중 연결 동시 처리 (멀티스레드 검증)

  # 터미널 1 — 서버
  nc -l -p 8000 -k   # -k: keep listening after disconnect

  # 터미널 2 — 프록시
  ./proxy --config ../config.json

  # 터미널 3 — 동시 연결 4개
  for i in {1..4}; do echo "client $i" | nc localhost 8080 & done

  프록시 로그에 total=4 가 찍히면 멀티스레드 accept 루프 정상 동작.

  ---
  시나리오 4: Ctrl+C graceful shutdown

  # 프록시 실행 중 Ctrl+C
  ^C
  # 출력: Received signal 2, shutting down...
  # 출력: Proxy stopped
  # 출력: Total connections: N

  ---
  주의사항

  - port 80은 root 권한 필요 → target_port를 8000 이상으로 설정 권장
  - verbose: true로 설정하면 DEBUG 로그까지 출력됨
  - 프록시는 같은 머신 내 포트 간 포워딩이므로 target_ip: "127.0.0.1" 그대로 사용 가능
